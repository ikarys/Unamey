Help

This page takes you from a product description to a pack of files for a coding agent. It covers setup, generation, comparison, pages, export, sharing, account settings, and fixes.

First run

Unamey runs in two modes. Local mode is the default: one person, no account, no login, and the app opens directly. Multi-user mode appears when the server was started with the public origin set in STUDIO_ORIGIN. You then see a login page. Click Create account. The first account becomes the admin and keeps everything made in local mode. Later accounts see only their own projects.

Set a model before generating anything. The database starts empty. Click the model name in the top bar to open Settings. Admins also find it under Admin and Models. Enter an OpenAI-compatible endpoint that accepts tool calls, an API key, and the models to use. You can add optional prices and choose how many variants run at once: 1 for a local model, up to 3 with an API. Routes: the active model draws the pages, an optional cheaper planner model writes the briefs and directions, and up to 5 fallback models are tried when a model errors.

After just dev, while cargo compiles, /api may answer 503 for a while. Wait, then reload. Installation and the run commands are in the Run section of the site. The top bar has a language switch, English or Français, and a light / dark toggle. Press ? in the admin area to list shortcuts.

Describe your product

On the home page, the title is "What are we designing?". Enter a description of the product, its users, and the feel you want. A useful description names the users, the data the app handles, the main task, the density, and any colours you want. For example: "A booking tool for a small yoga studio: classes, members, payments. Calm and modern."

The setup stepper has "Project", "Style", and "Options". Choose "New project (named from your prompt)" or an existing project. An existing project keeps its screens. Choose one of sixteen styles, or click Surprise me for 3 styles to compare. Click See the styles to open the Styles page.

In "Options", set "Theme" to Auto, Light, or Dark. Set "Target" to Auto, Desktop 1440 px screens, or Phone 390 px screens. Set "Variants". You can add colour wishes in your words and 1 to 5 screenshots of an existing app. The model drafts the brief from them without copying their look. Review the summary, then click Generate N screens.

Choose styles

The Styles page shows examples under "Styles". Each example shows the same product drawn in a different style. The two groups are "Work tools" and "Playful". Work tools cover dashboards, back offices, and apps people use for their job. Playful covers games, quizzes, and apps for the public, kids, or teens.

Examples include Editorial, which is light, paper-like, and uses serif titles; Brutalist, with black borders and square corners; Swiss, with a strict grid; Ledger, for admin forms and zebra tables; and Comic, with thick outlines and halftone fills. A style sets the layout and the mood: light or dark, colour family, and fonts.

Click Use this style on the example you want. The example is only an illustration. Your screen keeps the style, but its content, exact colours, and layout follow your product. If you are unsure, return to the home page and use Surprise me to compare 3 styles.

Compare and rework

During generation, one model call expands your description into a brief. You can review and edit it with Edit and Continue. Your words stay binding: the expansion cannot narrow the scope, rename the product, or drop a colour you asked for. For each variant, a planner picks one of 16 structures and a style, different across variants.

The studio shows looks side by side, with the brief on the left and token controls on the right. The right column adjusts colours and fonts live. Click Compare side by side to view two screens and pan both at once.

On each screen, record a "Verdict": good, mixed, or bad. Versions are new takes on this screen with the same look, pushed in one direction: bolder, quieter, distill, typeset, colorize or layout. A layout-only instruction, such as "move the filters above the table", keeps the structure and changes the arrangement. Token edits save a new version. Use "Same app, drawn in another style:" to add a variant in another style. Every result is a new screen next to the previous ones.

Pick the look and add pages

The project panel on the left shows "Project", "Concept", "Looks (N)", and "Pages". A project can hold several concepts; click + New concept to add one. Pick the look you like, then click Use as the project's look. Once a look is set as the concept reference, you can add pages.

Use "Page…" with "Page name", for example Settings, and "Page description": what this page shows and lets people do. Set "Target" to "Desktop", "Phone", or both. Both makes a desktop page and its mobile version in one batch. Click Generate page.

Pages reuse the look of #id: archetype, tokens, and shell. Mobile pages are their own screens: 390 px, a bottom tab bar, and 44 px targets. If you switch the reference look later, the pages already made keep their look; each can be regenerated in the new one.

Export the pack and brief your agent

Click Download pack (.zip). The zip contains a ui-pack/ folder with SKILL.md, tokens.css, reference.html, and pages/<page>.html or pages/<page>.mobile.html. SKILL.md holds the product, chosen style and structure, shell, tokens, do and don't rules, and pages. On the server, packs are also written under packs/<project>/.

Unzip the pack into your app as <app>/.claude/skills/ui-pack/. Ask the coding agent to build the screens following that skill. A useful prompt is: "Build the Settings screen following the ui-pack skill. Reuse its shell, tokens and page structure; do not invent another style."

Showcase makes a PNG of a screen in a browser window or a phone frame, for a pitch or a landing page. It needs Chromium, chromium on PATH, on the server. Without it, the PNG export and URL capture are unavailable; the rest works.

Gallery and sharing

The Gallery shows "Every screen you generated, by project." Use "Search screens" to find a screen. Filter by verdict: all, good, mixed, bad, or none. Filter by archetype. Badges mark "Reference", "Main screen", and "Mobile". Select several screens and click Delete N. The warning says "This cannot be undone." You can rename or delete a project. Projects can be archived.

Click Share to open "Share link". Choose scope: "The whole concept" or "This screen only". Anyone with the link sees the screens, read-only, without an account. The pack stays private. Choose "Link expiry" or "No expiry". Click Create link, then Copy. The note says "Copy it now: for security the link is not stored and cannot be shown again." You can revoke items in "Active links". Anyone using a revoked link loses access.

Your account

This section applies to multi-user mode only. The account page has "Profile", "Security", and "Usage". Profile shows name, email, role Admin or Member, member since, and sign out. Security has Change password, which requires at least 8 characters and signs out other sessions. It also lists "Sessions": devices signed in, with Revoke and Revoke other sessions. Usage shows screens and projects this month, totals, and screens per month over the last 6 months.

Delete my account removes all projects, generations, and packs. The admin account cannot be deleted. In the admin area, the first account sees "Models", "Users", "Jobs", and "Cache". View as member lets the admin check what a normal user sees.

Troubleshooting

  • The page says /api answers 503: cargo is still compiling after just dev. Wait and reload.
  • "unreachable" next to the model name: the endpoint URL is wrong or the server is down. Check Settings and that the endpoint accepts tool calls.
  • A screen comes out truncated or half drawn: the model stopped early. Small local models do this. Retry, lower the variants to 1, or route a stronger model.
  • Generation fails on a provider error: the fallback models are tried in order. Check Jobs in the admin area for the log.
  • No PNG / showcase: Chromium is not installed on the server.
  • Multi-user mode asks for a login you do not have: ask the admin for the instance to create your account from the login page.

Something else? Open an issue on GitHub with the model you use and what you saw.
